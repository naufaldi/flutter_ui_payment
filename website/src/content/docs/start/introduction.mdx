`flutter_ui_payment` provides widgets for checkout, payment status, receipts and optional identity verification (KYC). It includes pending, failed and unknown-result screens, manual payment instructions and host-owned authorization.

The package also includes forms, navigation, action menus, sheets, charts, feedback, video controls, promotions and transaction history.

## What the kit owns, and what you keep

The package renders structured data from your app and reports user intent through callbacks. It does not process money, make network calls, or need a router, state manager, camera or payment SDK.

| Concern | Owner | What the kit does |
| --- | --- | --- |
| Input, focus, local validation | Widget | Interaction and presentation-level validation |
| Identity rules, consent policy | Host | Renders the host's fields, validators and reasons |
| KYC decision, document validation | Host/backend | Shows progress, structured errors and the result |
| Price, fees, limits, quote expiry | Host/backend | Renders the snapshot; asks for re-approval when terms change |
| PIN/OTP/biometric challenge | Host auth SDK | Shows the challenge state; never receives the secret |
| Payment status, idempotency, refund | Host/backend/provider | Renders authoritative snapshots; never infers success |
| Polling, recovery, lifecycle | Host coordinator | Exposes callbacks; widgets never poll on their own |

"Host" means your app and the backend behind it. [Host-owned decisions](/concepts/host-owned/) explains each row.

## Invariants the kit helps keep

Start with [Blocks](/blocks/) to run and copy a complete mobile screen. Patterns
explain payment and KYC behavior; Guides cover layout, forms and loading states.

- `verified` comes only from the host, never from a finished upload.
- One active submit per attempt. `PaymentButton` locks while its callback runs; this is interaction protection, not a replacement for server-side deduplication.
- Timeouts, offline refreshes and an elapsed countdown never become "failed" or "paid".
- Older or duplicate snapshots cannot overwrite newer ones; a success changes only through an official provider correction.
- A changed total or method requires review and a new authorization.
- Refunds are a separate lifecycle shown beside the original payment.
- No KYC documents, PINs or credentials in public models; the host stores only an opaque attempt reference for recovery.

## Status

Version `0.1.0` is available from the [GitHub repository](https://github.com/naufaldi/flutter_ui_payment). It is not published to pub.dev, and the package name has not been checked for availability. All example data is synthetic.

Documentation captures use Flutter 3.44.6 on a 360×640 dp Android API 37 phone emulator and a 1280×800 dp Android tablet emulator. See [Compatibility](/reference/compatibility/) for platform requirements and verification coverage.

The kit targets iOS and Android phones and tablets. The web build is a documentation preview; desktop is outside the supported product scope.

Current verification limits:

- The 30-minute checkout integration goal has not been tested with an external developer.
- The Flutter web gallery has not been browser-tested.
- Android 7–10 has not been runtime-tested.
- pub.dev name availability and publishing checks have not been completed.
