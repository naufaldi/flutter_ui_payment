Every widget takes its colors, radius, spacing and amount style from `PaymentTheme`, a `ThemeExtension`. Register it on `ThemeData.extensions`. When no extension is installed, widgets fall back to `PaymentTheme.fromColorScheme`, so the kit follows your `ColorScheme` by default and a full brand is opt-in.

## Follow your scheme, then adjust

Buttons also support a dedicated `PaymentButtonTheme` and per-instance `PaymentButtonStyle`. See [Button customization](/components/button/#customization) for precedence, supported properties and preserved states; these overrides do not change other component families.

Fields (text, search, text area, select, date, date range and currency) have a dedicated `PaymentFieldTheme` for fill, resting outline, corners and input typography, with no per-field style. See [Text field customization](/components/text-field/#customization).

Other component families read the shared theme. Scope `PaymentTheme` to a feature to change its appearance; toasts capture the caller's scoped themes when shown. The host checkout example shares a button theme, field theme and named pay-button preset across two layouts.

```dart
final scheme = ColorScheme.fromSeed(seedColor: brandColor);

ThemeData(
  colorScheme: scheme,
  extensions: [
    PaymentTheme.fromColorScheme(scheme).copyWith(accent: brandColor, radius: 12),
  ],
);
```

Status tones (`info`, `success`, `warning`, `danger`) are fixed, contrast-checked values in `fromColorScheme`: at least 5.8:1 on white in light mode and 7.6:1 on `#131417` in dark mode, so status text stays readable whatever your seed color is. `neutral` follows the scheme.

## Light and dark

Build one `PaymentTheme` per brightness. This is the example app's default brand, "Hairline" (white page, navy-black ink, rules instead of cards), copied from `example/lib/themes.dart`:

```dart
ThemeData buildTheme(Brightness brightness) {
  final dark = brightness == Brightness.dark;
  final ink = dark ? const Color(0xFFECEDF0) : const Color(0xFF1A1F36);
  final surface = dark ? const Color(0xFF131417) : Colors.white;
  final scheme = ColorScheme.fromSeed(
    seedColor: const Color(0xFF1A1F36),
    brightness: brightness,
    dynamicSchemeVariant: DynamicSchemeVariant.monochrome,
    primary: ink,
    onPrimary: surface,
    surface: surface,
    onSurface: ink,
  );
  final payment = PaymentTheme.fromColorScheme(scheme).copyWith(
    accent: ink,
    onAccent: surface,
    surface: surface,
    surfaceMuted: dark ? const Color(0xFF1C1E23) : const Color(0xFFF5F6F8),
    outline: dark ? const Color(0xFF2C2E35) : const Color(0xFFE3E6EC),
    textPrimary: ink,
    textSecondary: dark ? const Color(0xFFA2A8B5) : const Color(0xFF5E6678),
    // Control edge 3.37:1 light, 4.85:1 dark.
    border: dark ? const Color(0xFF7E838E) : const Color(0xFF868C9A),
    disabled: dark ? const Color(0xFF62656E) : const Color(0xFFA6ABB5),
  );
  return ThemeData(colorScheme: scheme, extensions: [payment]);
}
```

Pass `theme: buildTheme(Brightness.light)` and `darkTheme: buildTheme(Brightness.dark)` to `MaterialApp`.

## System bars on Android

Your app controls system bars. On Android 15 and later, the navigation-bar contrast scrim can follow the window theme while your app uses another theme. Enable edge-to-edge in `main()`, then wrap the app in an `AnnotatedRegion` inside `MaterialApp.builder`. That context reads the resolved app theme, including an in-app theme switch.

```dart
import 'package:flutter/material.dart';
import 'package:flutter/services.dart';

void main() {
  WidgetsFlutterBinding.ensureInitialized();
  SystemChrome.setEnabledSystemUIMode(SystemUiMode.edgeToEdge);
  runApp(const MyApp());
}

// Inside MyApp.build:
MaterialApp(
  theme: buildTheme(Brightness.light),
  darkTheme: buildTheme(Brightness.dark),
  themeMode: themeMode,
  builder: (context, child) => AnnotatedRegion<SystemUiOverlayStyle>(
    value: SystemUiOverlayStyle(
      systemNavigationBarColor: Colors.transparent,
      systemNavigationBarDividerColor: Colors.transparent,
      systemNavigationBarContrastEnforced: false,
      systemNavigationBarIconBrightness:
          Theme.of(context).brightness == Brightness.dark
              ? Brightness.light
              : Brightness.dark,
    ),
    child: child!,
  ),
  home: home,
);
```

The transparent bar and divider let the app surface continue behind gesture and three-button navigation. Light icons belong on dark surfaces, dark icons on light surfaces. Status-bar fields stay null so the app bar keeps control of the status bar. The kit sets no SystemUiOverlayStyle.

## Tokens worth knowing

The full token reference, with swatches and values, is in Foundations: [Color](/foundations/color/), [Typography](/foundations/typography/) and [Spacing and radius](/foundations/spacing/). The tokens that matter most when you set a brand:

- **`outline`** is the decorative hairline: dividers, the method-group edge, the action-bar top. It may sit below 3:1.
- **`border`** is the edge of a control (inputs, secondary buttons, unselected checkboxes) and must reach 3:1 against `surface`. It defaults to `textSecondary` a quarter of the way to `surface`.
- **`disabled`** is the label and icon color of a disabled control on `surfaceMuted`.
- **`radius`** is the corner radius of selectable boxes such as the method list, and the base of the other corner roles: tags use half of it, controls three quarters, sheets one and a half. To change one role on its own, see [Corner roles](#corner-roles).
- **`spacing`** is the base unit (default 8). Layouts use multiples by role: inline 4, related 8, block 12, group 16, section 24, major 32.
- **`amountWeight`** and **`amountFontFamily`** style money. Amounts use tabular figures.
- **`referenceFontFamily`** is for things people copy or compare digit by digit: virtual account numbers, transaction IDs, promo codes. It defaults to the platform monospace.

The package bundles no fonts. Use your app's text theme for everything else.

## Default shape and type

Without corner overrides, the base radius is 8 dp:

| Role | Default | Derivation |
| --- | --- | --- |
| Box | 8 dp | `radius` |
| Control | 6 dp | `radius * 0.75` |
| Sheet/dialog | 12 dp | `radius * 1.5` |
| Tag | 4 dp | `radius * 0.5` |

`PaymentType` takes the font family and fallback from `textTheme.bodyMedium`, but defines its own sizes and line heights: body 15/22, label and heading 15/20, input 16/24, title 17/24, caption 13/18 and tag 12/16. Changing the host's body-medium font size does not resize these roles. Text still follows the ambient text scaler. Use `PaymentButtonTheme` for button typography and `PaymentFieldTheme.textStyle` for entered text/placeholders; field labels and helper/error text keep their roles. See [existing-app adoption](/start/existing-app/) for a complete brand bridge.

## Corner roles

<Screens><Screen name="android_catalog_theme_shape_roles_variants" dark="android_catalog_theme_shape_roles_variants_dark" alt="Default corners beside a product theme with square boxes, pill badges, unchanged controls and rounder sheets." caption="Independent corner roles" /></Screens>

Most brands only set `radius`, and every corner follows it. When one role needs its own shape, set it on the theme once. Here boxes are square, tags are pills, sheets are rounder and controls keep their default 6:

```dart
PaymentTheme.fromColorScheme(scheme).copyWith(
  radius: 0, // boxes such as the method list
  tagRadius: 999, // badges and tags
  controlRadius: 6, // buttons, inputs, notices, menus
  sheetRadius: 20, // sheet tops and dialogs
);
```

Leave a role unset and it keeps its multiple of `radius`: tag 0.5, control 0.75, sheet 1.5. Zero gives square corners; values must be finite and not negative. Components read the roles through the theme, so call sites need no style. A light/dark switch animates from the corner each theme draws, including a derived one.

`copyWith` keeps a role once set; passing null does not reset it. Build a new `PaymentTheme` to go back to the derived value. To change only buttons, use [`PaymentButtonTheme`](/components/button/#customization) instead; to change only fields, use [`PaymentFieldTheme`](/components/text-field/#customization).

The example's `compositions/host_checkout.dart` uses one host model and callback set for these two arrangements. `ProductLooks` installs reusable Button and Field themes while preserving other extensions; `payActionStyle(context)` resolves a shared host preset from current tokens. Everyday controls use those defaults. The invoice stacks method choice and receipt details; the wallet review groups balance and review content and ends with an action bar.
