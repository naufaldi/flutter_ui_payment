The kit ships two languages: English (`en`) and Indonesian (`id`). Every widget reads its strings from `PaymentLocalizations`.

## Register the delegate

```dart
MaterialApp(
  localizationsDelegates: const [
    PaymentLocalizations.delegate,
    GlobalMaterialLocalizations.delegate,
    GlobalWidgetsLocalizations.delegate,
    GlobalCupertinoLocalizations.delegate,
  ],
  supportedLocales: const [Locale('id'), Locale('en')],
);
```

The `Global…` delegates come from `flutter_localizations` (add it to your `pubspec.yaml`). Without `PaymentLocalizations.delegate`, widgets still pick a language from the ambient locale: Indonesian for `id`, English otherwise. `PaymentLocalizations.supportedLanguages` is `['en', 'id']`.

The strings for the interaction, navigation, sheet, media, promotion and transaction components live in the `KitStrings` extension on `PaymentLocalizations`, so you keep one delegate.

## Money

`Money` is an integer number of minor units plus a currency code. Arithmetic never uses floating point, and mixing currencies throws.

```dart
const price = Money.idr(100000); // Rp100.000 (IDR has no minor digits)
const fee = Money(250, 'USD'); // $2.50
final total = price + const Money.idr(2500);
```

`MoneyFormat` formats and parses per locale. Only the separators differ: `id` groups with `.` and uses `,` for decimals, `en` does the opposite. Get the active one from `PaymentLocalizations.of(context).moneyFormat`.

```dart
final format = PaymentLocalizations.of(context).moneyFormat;
format.format(const Money.idr(102500)); // "Rp102.500" in id, "Rp102,500" in en
format.spoken(const Money.idr(102500)); // "102500 IDR", for screen readers
```

`CurrencySpec` knows IDR, USD and SGD. Register others with `CurrencySpec.register`; an unknown code falls back to the code as its symbol and two minor digits.

## Strict parsing

`MoneyFormat.parse(text, currency)` accepts a currency symbol or code, spaces and correctly placed group separators. Input that could be read two ways is rejected as `AmountIssue.ambiguous` instead of being guessed. For example, `100,000` for IDR under `id` is rejected: it could be one hundred thousand or one hundred with a decimal part.

```dart
final result = format.parse(input, 'IDR').withinLimits(
  minimum: const Money.idr(10000),
  maximum: const Money.idr(5000000),
);
if (result.isValid) {
  submit(result.money!);
} else {
  showError(result.issue!); // empty, invalidFormat, ambiguous, negative, zero, …
}
```

`AmountInput` does this for you and shows localized errors after the field loses focus or on submit.

## Dates

`PaymentLocalizations.formatDateTime` prints "30 Oct 2026, 14:05" in English and "30 Okt 2026, 14.05" in Indonesian, in the device time zone.
