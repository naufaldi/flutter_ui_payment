Use Collection for documents, OCR history, notes, or other records that need
their own row layout. Import `PaymentCollection` when your host supplies the
page controls and state content. Copy the [Load more block](#copy-the-load-more-block)
when you want a ready-made append and retry example.

## Import a viewport

Give the collection finite width and height, for example in a `Scaffold` body
or an `Expanded` child of a bounded `Column`. It already scrolls. For
pull-to-refresh, wrap it in a `RefreshIndicator` and pass
`AlwaysScrollableScrollPhysics` so short and empty pages can refresh too.

```dart
import 'package:flutter/material.dart';
import 'package:rakit_ui/rakit_ui.dart';

Widget documentCollection({
  required List<({String id, String title})> documents,
  required Widget stateContent,
  required Future<void> Function() refreshCurrentPage,
  required double bottomClearance,
  Widget? pager,
}) {
  final indexByKey = {
    for (final (index, document) in documents.indexed)
      ValueKey(document.id): index,
  };
  return RefreshIndicator(
    onRefresh: refreshCurrentPage,
    child: PaymentCollection(
      rowCount: documents.length,
      rowBuilder: (context, index) {
        final document = documents[index];
        return Text(document.title, key: ValueKey(document.id));
      },
      findItemIndexCallback: (key) => indexByKey[key],
      placeholder: stateContent,
      footer: pager,
      physics: const AlwaysScrollableScrollPhysics(),
      padding: EdgeInsets.fromLTRB(16, 16, 16, bottomClearance),
      maxContentWidth: 448,
    ),
  );
}
```

- Pass only the current page's rows for numbered paging, or accumulated rows
  for append paging. The builder runs on demand; no record type is required.
- If a refresh or sort can reorder mounted rows, key each row by its stable
  record ID and supply `findItemIndexCallback`. Return the row's zero-based
  index in the new snapshot, excluding separators, or `null` if it was removed.
  Keep the collection mounted so row state can follow the key.
- With zero rows, `placeholder` can show your branded loading, empty or error
  widget. With rows, the placeholder is ignored. Supply accessible labels and
  error announcements in your state widgets.
- `footer` scrolls after either the rows or the placeholder. Leave Previous on
  an empty later page if the server allows it. Hide the pager when the host
  has no valid navigation targets, such as an initial load.
- Use `padding` for host insets, including clearance for a floating bar.
  `maxContentWidth` caps the whole content column inside those insets. When
  `padding` is omitted, the viewport uses the theme's group spacing.
- Keep query, account and page identity in your app. Replace rows only with
  responses for the active request; discard stale successes and failures.
  Retry the failed page. To keep scroll offsets separate across pages or
  queries, give each identity a different `PageStorageKey`, or manage the
  offset with a host-owned scroll controller.

## Copy the Load more block

From `example/`:

```sh
flutter run -d <device-id> -t lib/collection_block_demo.dart
```

Or open **Collection** in Gallery to try the sample document cards. In the
standalone demo, the scenario menu can start with an empty list, return an
empty next page, or fail the first or next page once. Use **Load more** and
**Retry** to try paging and recovery. The demo uses synthetic data only.

## Assemble it in your host

Copy `collection_block.dart` and `paged_block_footer.dart`. Give the block a
bounded viewport such as a `Scaffold` body. It already scrolls; do not nest it
in another vertical scroll view. Pass the accumulated `rowCount`, a
`rowBuilder` that reads your records by index, and the current `pageState`.
Supply your localized labels and a `StateMessage` for the first empty page.
Use the optional `header` for content that should scroll with the list.

| Host state | What the block shows |
| --- | --- |
| `loading` with no rows | Initial skeleton |
| `ready` with no rows | First-page empty copy, optionally with an action such as Upload PDF |
| `moreAvailable` | Existing rows and Load more |
| `loading` with rows | Existing rows and a busy Load more button |
| `CollectionPageFailure` | Retry; with rows, the error stays beside them instead of replacing the list |
| `laterEmpty` | Earlier rows and an end-of-list message, without a first-page action |
| `ready` with rows | Completed collection, without a pager action |

Bind `onRequestPage` to your host. Ignore repeated requests while one is
pending. Keep the cursor and rows until the request succeeds; on failure, use
safe display copy and a distinct `attempt` even if the message is unchanged.
The block publishes the live error only when it enters the viewport and does
not pull a reader back to a footer they have scrolled away from.

On a query or collection change, start a new request generation and discard
old successes and failures. Give the block a `PageStorageKey` for the active
generation if the new collection should start at the top. The demo treats an
empty next page as terminal. If your backend can return empty intermediate pages
with a valid next cursor, normalize them before passing a terminal state.
Authorization, routing and data access stay in your app.

The sample card is a `PaymentBox` built by the host row builder, not a required
row type. Use [Rakit's public theme](/concepts/theming/) to set the surface,
spacing and typography, and use your own widgets for row actions. The copyable
source is unchanged; it does not require `PaymentCollection`.
