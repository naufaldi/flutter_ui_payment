Use this general-purpose Authentication block when the host owns account
creation and decides whether email verification is required. The details step
validates email and password locally, explains the password policy, links to
the host's policy, reports host failure and can continue to a verification
code step without becoming an identity service.

## Run and try

From `example/`:

```sh
flutter run -d <device-id> -t lib/auth_blocks_demo.dart
```

Open **Create account** from Login. Use any valid email and a password such as
`notes123`. In **Email verification required**, the synthetic host asks for the
fixture code `248913`; a wrong code fails safely and resend is host-owned. In
**Registration continues directly**, a successful registration navigates Home.
The demo is Annota-themed but is not Annota's production authentication,
policy or account system.

## Composition and boundaries

`RegisterBlock` is self-contained apart from the package. The host chooses
`RegisterBlockStep.details` or `.verification` and supplies `onSubmit`,
`onVerify`, `onResendVerification`, `onLogin`, `onPolicy`, `busy` and a safe
`errorText`. The block never creates an account, sends email, stores secrets,
writes a consent record or verifies a code itself.

| UI | Existing library surface |
| --- | --- |
| Phone and wide page layout, title navigation and pinned action | `PaymentFullPageView` |
| Email and verification-code input | `PaymentTextField` |
| Submit, verification and resend states | `PaymentButton` |
| Host failure announcement | `PaymentBanner` |
| Login and policy navigation | `PaymentLink` |

The password control is deliberately host code inside the copied file. The kit
does not accept secrets or provide a password-input mode (D1a); the host owns
secret input, credential handling, account policy, consent records, verification
delivery and routing. Pair it with [Login](/blocks/login/) for the connected
authentication flow.

## Proof and limits

Widget tests cover password policy validation, host failure and retry, policy
navigation, host-required verification, wrong-code recovery, and the connected
home destination. Android captures cover light, dark, failure, verification and
enlarged text. Connect your own account backend, verification service, consent
records, abuse controls and navigation before production use.
