Explain what data the host collects and why before asking for consent. The
consent box starts unchecked and Continue waits for it. The person then fills the
host's identity fields, reviews them with the ID number masked and saves.
Saving details never verifies identity; the document photos come next.

## Run and try

From `example/`:

```sh
flutter run -d <device-id> -t lib/kyc_onboarding_demo.dart
```

Check the consent box and continue, fill the synthetic form, review and save.
The developer menu offers **NIK ditolak host** (the host rejects the ID number
after a check; the person corrects only that field) and **Simpan gagal** (the
first save fails and keeps the details). Changing a fixture starts a fresh
synthetic session and ignores answers from the previous one.

## Composition and boundaries

`KycOnboardingBlock` takes a typed step, the host's requirement list, field specs,
values, server errors, an `IdentityFormController` and callbacks. The host
records consent, runs its own field rules and saves the details. The form keeps
what the person typed across host answers.

| UI | Existing library surface |
| --- | --- |
| Purpose list, consent and policy link | `VerificationIntro` |
| Host fields, validation and server errors | `IdentityForm`, `IdentityFieldSpec`, `IdentityFormController` |
| Steps, error slot and pinned action | `PaymentOnboardingView`, `PaymentTaskListItem` |
| Saved state | `PaymentBanner` |

The block collects no PIN, OTP, password or document bytes. The host owns the
privacy policy, consent records, retention, field rules and identity checks.
All identities in the demo are fictional. See the
[verification pattern](/patterns/verification/) and the
[forms guide](/patterns/forms/). Continue with the
[KYC capture block](/blocks/kyc-capture/) for the photos.

## Proof and limits

Tests prove that consent starts unchecked and Continue waits for it, that the
form asks for no PIN or OTP, that a host-rejected ID number is corrected in place
and reviewed masked, that a failed save keeps the details and a confirmed save
still says identity is not verified, and that consent and Continue stay reachable
at 320 dp and 200% text in dark mode with reduced motion. Android captures were
inspected. No hardware speed or iOS visual claim. The demo is not an identity
service.
