Use this general-purpose Authentication block when a host already owns its
identity backend. It validates the email and password locally, keeps the
password in host-owned input with a show/hide action, reports a safe host
failure, and leaves authentication, recovery and navigation to the host.

## Run and try

From `example/`:

```sh
flutter run -d <device-id> -t lib/auth_blocks_demo.dart
```

The connected demo uses an Annota-derived illustrative host theme and synthetic
fixtures only. It is not Annota's production authentication flow: nothing
leaves the device, no account is created or stored, and no secret is logged.
Use `mina@example.com` / `notes123`. The default scenario makes the first
sign-in fail so the recovery path is visible; the second succeeds and the host
navigates Home. The developer menu also starts the registration scenarios.

## Composition and boundaries

`LoginBlock` is self-contained apart from the package. `LoginCredentials` is
the only value passed across the authentication boundary. The host supplies
`onSubmit`, `onForgotPassword`, `onRegister`, `busy` and a safe `errorText`.
The block never authenticates, stores, transmits or logs a credential.

| UI | Existing library surface |
| --- | --- |
| Phone and wide page layout, title navigation and pinned action | `PaymentFullPageView` |
| Email input and validation error presentation | `PaymentTextField` |
| Submit and recovery action states | `PaymentButton` |
| Host failure announcement | `PaymentBanner` |
| Registration navigation | `PaymentLink` |

The password control is deliberately host code inside the copied file. The kit
does not accept secrets or provide a password-input mode (D1a); the host owns
secret input, credential handling, rate limits, recovery and routing. Continue
with [Register](/blocks/register/) for account creation and host-required
verification.

## Proof and limits

Widget tests cover invalid input, show/hide password, host failure and retry,
busy locking, recovery navigation, the connected home destination, and 320 dp
at 200% text. Android captures cover light, dark, failure and enlarged text.
Connect your own identity provider, throttling, audit policy, account recovery
and navigation before production use.
