and amounts are synthetic.

A block can use several patterns. Follow its pattern links for the payment or KYC
rules behind the screen.

## Adoption order

1. Install the [package](/start/installation/) and configure shared theme tokens.
2. Copy the block source and supply your host models and callbacks.
3. Apply a scoped family theme when the product needs a shared component look.
4. Use a named host preset for a repeated subset, then an inline override only
   for a justified exception. See [theming](/concepts/theming/).

You own auth, networking, durable attempt persistence, quotes and status verdicts,
plus routing and platform effects. Demo adapters are not production integrations.
Connect the block to your authenticated backend and review your provider's integration requirements before accepting real payments.

## Roadmap and references

The [Payment/KYC block tracker #223](https://github.com/naufaldi/flutter_ui_payment/issues/223)
records the work behind this set. Every block listed above has source and a runnable demo.

We use [shadcn Blocks](https://ui.shadcn.com/blocks) as a reference for visible
preview/source/file composition, [Flutter Templates Finance](https://www.fluttertemplates.dev/widgets/finance/)
for mobile screen categories, and [FlockUI](https://www.flockui.com/) for copying
Dart source into a host app. These are design references; the blocks use this kit's
components and payment/KYC behavior.
