payments without requesting another payment. The balance is the single display
amount; section totals and metadata recede. Content scrolls rather than shrinking
to fit a phone. The host shell owns bottom navigation and safe areas.

## Run the demo

From the repository's `example/` directory:

```sh
flutter run -d <device-id> -t lib/merchant_demo.dart
```

**Periksa transaksi** opens three synthetic unknown records. **Lihat semua**
opens all records. Tap a record to inspect its details. Settings switches the
theme. No payment, clipboard write, network call or status verdict is performed.

The same block also runs in the Soft host preset, framed in a host inset panel on
a tinted page. See [Theming](/concepts/theming/#soft-a-third-preset):

```sh
flutter run -d <device-id> -t lib/soft_merchant_demo.dart
```

## How it is assembled

| Section | Library components |
| --- | --- |
| Balance | `AmountText` with the `display` variant |
| Notice and inspection action | `PaymentBanner`, `PaymentLink` |
| Revenue and method mix | `ChartModule`, `PaymentBarChart`, `PaymentMeterChart` |
| Recent records | `TransactionListItem`, `TransactionRecord` |
| Transaction detail | `PaymentSheet`, `PaymentSheetHeader`, `StatusHeader`, `PaymentButton` |
| Hierarchy and rhythm | `PaymentType`, `PaymentTheme`, `PaymentSpace`, `PaymentSection` |

The host supplies authoritative totals, method percentages and unconfirmed count,
which may include records outside the preview. Null balance means unavailable,
never zero. The detail scenario covers confirmed and unknown only; map other
provider states explicitly in your host. A dismissed sheet never changes status.
Read the [history pattern](/patterns/history/) and
[status/recovery pattern](/patterns/status-receipt/) before integrating.

## Verification and limits

Widget tests cover transaction inspection, unavailable and empty data, and a reachable 48 dp detail action at 320 dp with 200% text. The demo starts with a fixed data snapshot; add host loading, retrieval and reconciliation. See [Compatibility](/reference/compatibility/) for device coverage.
