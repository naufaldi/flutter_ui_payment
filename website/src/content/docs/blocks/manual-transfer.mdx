Show the exact virtual account number and amount the host issued, let the payer
copy the number, and check the status of the same payment attempt. The deadline
tells the payer when to transfer by. Reaching it is never a payment verdict:
only the host's status says whether the money arrived.

## Run and try

From `example/`:

```sh
flutter run -d <device-id> -t lib/manual_transfer_demo.dart
```

Tap the copy icon: the demo's host adapter writes the number to the clipboard.
Tap **Cek status**; the synthetic host confirms success for the same attempt.
The developer menu offers four scenarios:

- **Batas waktu lewat**: the countdown reaches zero and a warning appears. The
  status stays pending until **Cek status** returns the host's answer.
- **Cek status gagal**: the first check fails; the last known pending status and
  the account stay on screen and the next check succeeds.
- **Respons VA hilang**: the issuing response is unknown, so the kit hides the
  account. **Cek status** reconciles the same attempt and then shows the number.
  The block never offers a second transfer or a new attempt.

Changing a scenario starts a fresh synthetic session and ignores answers that
belong to the previous one.

## Composition and boundaries

`ManualTransferBlock` takes the host's `PaymentAttempt`, amount, a clock and
callbacks for checking status and copying. The host keeps the attempt durable
and calls `PaymentAttempt.reconcile` with every new snapshot; the kit drops
snapshots for another attempt, older revisions and downgrades.

| UI | Existing library surface |
| --- | --- |
| Status, amount and Check status | `PaymentStatusView`, `PaymentAttempt`, `Observation` |
| Account number, copy, amount and deadline | `PaymentInstructions`, `VirtualAccountInstructions` |
| Lost issuing response | `SubmissionState.outcomeUnknown` |

The clipboard, polling, deep links and bank instructions stay in the host. The
copy callback returns `false` when copying failed so the kit can say so. Every
account number and amount in the demo is fictional. See the
[status and receipt pattern](/patterns/status-receipt/) and the
[checkout pattern](/patterns/checkout/).

## Proof and limits

Widget tests cover the exact account and amount, same-attempt status checks, elapsed deadlines, failed checks and a reachable action at 320 dp with 200% text. The demo does not connect to a bank. See [Compatibility](/reference/compatibility/) for device coverage.
