## The hard states are the product

Payment screens need to handle missing responses, late status updates and changed totals. The kit provides these behaviors:

**The submit timed out after the server accepted it.** The screen says "Don't pay again." first, shows a hatched band that never looks like an ordinary pending state, and offers one action: check status, using the same attempt reference.

**An older status arrives after a newer one.** `PaymentAttempt.reconcile` rejects stale revisions, another attempt's data, a mismatched server reference, and a success that turns into anything else without an official provider correction.

**The total changed after the customer chose a method.** `PaymentConfirmation` shows the old and new total and keeps the confirm action unreachable until the customer accepts the new terms.

**The payment is still pending or unknown.** The UI offers no pay-again action. A new attempt is offered only when the host allows it and the previous attempt is final and not a success. Your backend must still enforce idempotency.

```dart
// Every status response goes through reconcile. Rejected snapshots leave the
// attempt as it was and tell you why.
final result = attempt.reconcile(snapshotFromYourAdapter);
if (!result.applied) debugPrint('ignored: ${result.rejection}');
attempt = result.attempt;

PaymentStatusView(
  attempt: attempt,
  amount: quote.total,
  onAction: (action) => host.handle(action), // only attempt.availableActions
);
```

## Who decides what

The widgets render data the host gives them and report what the customer did through callbacks. They make no network calls and need no router, state manager, camera or payment SDK.

| Concern | Owner | What the kit does |
| --- | --- | --- |
| Price, fees, limits, quote expiry | Host/backend | Renders the snapshot; asks for re-approval when terms change |
| PIN/OTP/biometric challenge | Host auth SDK | Shows the challenge state; never receives the secret |
| Payment status, idempotency, refund | Host/backend/provider | Renders authoritative snapshots; never infers success |
| Polling, recovery, lifecycle | Host coordinator | Exposes callbacks; widgets never poll on their own |
| KYC decision, document validation | Host/backend | Shows progress, structured errors and the result |

The full table, including input and consent, is on [Host-owned decisions](/concepts/host-owned/).
