## Usage

```dart
Scaffold(
  body: ListView(
    padding: const EdgeInsets.all(16),
    children: [
      const MerchantHeader(
        name: 'Ruang Bayar Akademi',
        category: 'Education',
        orderReference: 'RB-118',
        verified: true, // your verification flag
      ),
      const PaymentStepIndicator(
        steps: ['Verify', 'Checkout', 'Pay'],
        current: 1,
      ),
      PaymentSummary(quote: quote, previousQuote: previousQuote),
      PaymentMethodPicker(
        methods: methods,
        selectedId: selectedId,
        onChanged: (method) => requote(method.id),
      ),
      BalanceCard(
        state: host.balanceState, // sufficient, insufficient, unavailable
        balance: balance,
        shortfall: host.shortfall,
      ),
      PromoCodeInput(
        status: codeStatus, // idle, checking, applied, rejected
        onApply: host.applyCode, // Future<void> Function(String code)
        appliedCode: code,
        discount: discount,
        message: codeError,
        onRemove: host.removeCode,
      ),
    ],
  ),
  bottomNavigationBar: PaymentActionBar(
    total: quote.total,
    updating: requoting,
    action: PaymentButton(
      label: 'Review payment',
      onPressed: requoting ? null : review,
    ),
  ),
);
```

Then the review and the host challenge:

```dart
PaymentConfirmation(
  quote: quote,
  method: selectedMethod,
  previousQuote: previousQuote, // after a re-quote: forces re-approval
  onConfirm: () => host.revalidateAndAuthorize(quote), // returns a Future
);

AuthorizationPrompt(
  phase: authPhase,
  onStart: host.startChallenge,
  onBackToReview: backToReview,
);
```

## Behavior

- `PaymentSummary` leads with the total, then items, then every fee, discount and tax. Fees are never collapsed. With `previousQuote` it shows a notice with both totals.
- `PaymentMethodPicker` shows unavailable methods disabled with your `unavailableReason`. `PaymentMethodPicker.validSelection(methods, id)` returns `null` when a selected method disappeared or became unavailable, so you can clear it.
- `PaymentConfirmation` keeps `onConfirm` unreachable until the customer accepts a changed total.
- `AuthorizationPrompt` never receives a PIN, OTP or biometric result. Your SDK runs the challenge; you set the `AuthorizationPhase`. Canceled and failed have different copy, and neither is shown as a payment.
- `PaymentActionBar` pins the total and the main action. While `updating` is true it says "Updating total…"; disable the action yourself.
- For free-form amounts, such as a top-up, use [`PaymentCurrencyField`](/components/amount-input/).
- `BalanceCard` never compares the balance with the total, and `PromoCodeInput` never computes a discount. A discount reaches the price only as a new host quote with a `QuoteLineKind.discount` line.

## Pattern adoption

Changed-total approval uses `PaymentCheckbox`, aligned to the content gutter. Pay stays disabled until the customer accepts. Unavailable methods keep their reason below a muted label and show a thin disabled radio ring.

Promo code entry uses PaymentTextField with reference typography. Empty-code errors hide when editing starts.
