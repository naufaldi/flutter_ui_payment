A report or other focused task presented through existing sheets. Variants: small, large. Nothing else exists. Stripe size maps to showPaymentFocusView(size:), shown/setShown map to its Future and host dismissal, confirmCloseMessages maps to PaymentConfirmClose. On phones, including a phone in landscape (window shorter side under 600 dp, D92), it is a bottom sheet: small hugs content, large fills. On tablets it is a side panel 420/720 dp wide. Drag dismiss is disabled so it cannot bypass confirmation. Close, scrim, Escape and Back ask before discarding when confirmClose is supplied. Inline specimens do not block their host route.

## Usage

```dart
// example/lib/screens/gallery_views.dart
PaymentFocusView(
                  title: 'Report a problem',
                  confirmClose: PaymentConfirmClose(
                    title: 'Discard report?',
                    message: 'Your changes will be lost.',
                    exitLabel: 'Discard',
                  ),
                  child: PaymentTextArea(label: 'What went wrong?'),
                );
```

## Footer width

The footer stacks its actions at full width, primary on top, whenever the footer is narrower than 600 dp or the text is large (D59). Wider, the actions hug their labels at the end edge.

### States and content

The host supplies state and callbacks. Explain empty states and offer a next action. Use specific labels that wrap. Keep one primary action; separate destructive actions. Use semantic tokens and status text alongside visual marks.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: Use large only for a wider task; confirm close only when the draft is dirty.

**Don't**: Log report text or keep a clean sheet behind a discard prompt.

## Content guidelines

Use sentence case and name the payment fact or action. Keep instructions visible and use semantic type, color and spacing tokens.

Use large only for a wider task; confirm close only when the draft is dirty.

## Accessibility

Labels wrap at large text. Controls retain their keyboard and screen-reader behavior. The host owns navigation and side effects.

Report a problem (A02/H04) confirms closing only while the local draft is dirty. Sending returns a case ID; failure preserves the draft for retry.
