`StateMessage` replaces a list when there is nothing to show: no items yet, nothing matches a search, or the list failed to load. It is compact and left-aligned, so it reads as part of the list it replaces rather than as an illustration.

## Usage

```dart
// example/lib/screens/gallery_kit.dart
StateMessage(
            icon: Icons.bookmark_border,
            title: t('No saved billers', 'Belum ada tagihan tersimpan'),
            message: t(
              'Save a biller after paying to find it here.',
              'Simpan tagihan setelah membayar agar muncul di sini.',
            ),
          );
```

## Variants

Variants: neutral, info, success, warning, danger. Nothing else exists.

### Empty

Nothing exists yet. Say what will appear here and how to get it.

```dart
const StateMessage(
  icon: Icons.bookmark_border,
  title: 'No saved billers',
  message: 'Save a biller after paying to find it here.',
);
```

### No match

The list has items but none match the search or filter. Offer to clear the filter rather than a retry. `TransactionHistory` shows this state on its own.

### Error

Loading failed. Use `tone: StatusTone.danger`: the message is then announced to screen readers when it appears. Offer one way forward, usually "Try again".

### PaymentEmptyMessage

A required title explains missing module content; message adds context and actionLabel/onAction provide recovery. DataTable and detail modules use it for empty results. Do not replace it with an unlabelled icon.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: Explain why content is empty and offer recovery; danger is for primary-content failure.

**Don't**: Show only No data without context or an available next action.

## Content guidelines

- The title says what happened: "No saved billers", "No payments match ‘pulsa’", "Couldn’t load billers".
- The message is one line on why or what to do next.
- One action at most. If there is nothing the person can do, leave it out.
- The headline carries the meaning, so the icon stays muted in every tone.

Explain why content is empty and offer recovery; danger is for primary-content failure.

## Accessibility

- The message is one semantics container.
- `tone: StatusTone.danger` makes it a live region, so errors are announced. Other tones are read in place.
