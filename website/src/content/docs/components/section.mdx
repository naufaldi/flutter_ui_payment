`PaymentSection` groups related content under a title. Sections are flat: they sit on the page surface and are separated by space, never boxed, so they nest inside your own cards and sheets without stacking borders.

## Usage

```dart
// example/lib/screens/flow_screen.dart
PaymentSection(child: LoadingSkeleton(rows: 3, leading: false));
```

## Stripe → kit

No Stripe equivalent. Admitted because: Checkout and overview; Gallery Kit; this reusable payment composition keeps host state outside presentation.

## Variants

Variants: titled, untitled, trailing action. Nothing else exists.

### With a header action

`trailing` puts an action beside the title, such as "Edit". Keeping a section's action in its header saves a row and ties the action to the content.

```dart
PaymentSection(
  title: 'Identity',
  trailing: TextButton(onPressed: editIdentity, child: const Text('Edit')),
  child: identityRows,
);
```

### Without a title

`title` is optional. Without it the section is only vertical padding around its child, which keeps spacing consistent with titled sections.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: Use one short heading for a related block and a secondary trailing action.

**Don't**: Wrap already titled page modules just to add another heading.

## Content guidelines

- Titles are short nouns in sentence case: "Order summary", "Pay with".
- Use a section per topic. If a section needs a sub-section, consider an [expandable section](/components/accordion/) or a separate screen.
- Use a [divider](/components/divider/) between sections only when space alone does not separate them.

Use one short heading for a related block and a secondary trailing action.

## Accessibility

- The title is marked as a header, so screen-reader users can jump between sections.
