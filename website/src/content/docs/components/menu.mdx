## Usage

```dart
// example/lib/screens/gallery_nav_controls.dart
PaymentMenu(
          trigger: (toggle, node) => PaymentButton(
            label: 'Options',
            width: PaymentWidth.hug,
            variant: PaymentButtonVariant.secondary,
            size: PaymentSize.small,
            focusNode: node,
            onPressed: toggle,
          ),
          entries: [PaymentMenuItem(label: 'Download', onSelected: () {})],
        );
```

## Variants

Variants: item, group, custom trigger. Nothing else exists.

### Disabled entries

An entry with `onSelected: null` is shown disabled. Keep it in the menu when people would otherwise look for it; leave it out when it never applies to them.

### Destructive entries

`destructive: true` draws the entry's icon and label in the danger tone. Put destructive entries last and confirm them with a [dialog](/components/dialog/).

### Phone: action sheet

Below 600 dp the trigger opens a bottom action sheet instead of an anchored menu (D55):

- every entry is a full-width row at least 48 dp tall; when any entry has an icon, every entry keeps the icon column so labels share one edge;
- group titles become captions, and groups are separated by a divider;
- destructive entries move last, after a divider;
- a full-width quiet Cancel sits at the bottom, above the safe area.

The sheet closes first. Then the menu runs the entry's `onSelected` or reports its `id` to `onAction`, once, and focus returns to the trigger. Cancel, the scrim, swipe down and Escape close it without running anything.

### Wide: anchored menu

At 600 dp and wider the menu is built on MenuAnchor. Arrow keys move between entries, Escape closes the menu and focus returns to the button. The panel keeps 16 dp from the window edges. Entries without an icon keep the icon column when a sibling has one. The menu opens instantly: a menu used many times a day should not make people wait for it.

### Variants, behavior and migration

Migration: ActionMenu and ActionMenuEntry remain deprecated aliases until 0.2.0; rename to PaymentMenu and PaymentMenuItem. Old constructors keep compiling.

Use trigger: (toggle, focusNode) to return PaymentButton or PaymentIconButton. Pass both the toggle callback and focus node so closing restores focus.

[Button group](/components/button-group/) now composes related status and dialog actions. Overflow menus wrap long labels at large text.

**Migration (UI review P2):** on a phone, the callback runs after the sheet closes. A widget test that taps a phone menu entry and checks the callback after a single `pump()` needs `pumpAndSettle()`.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: Group related actions; keep the main primary action visible outside overflow.

**Don't**: Use action menus to imitate a form selector.

## Content guidelines

- Start each label with a verb: "Copy account ID", "Export history".
- Use sentence case and no end punctuation.
- Keep a menu to a handful of entries. Actions people need on every visit belong on the screen, not in a menu.

Group related actions; keep the main primary action visible outside overflow.

## Accessibility

Preserve reading order, visible labels and semantic descriptions. Interactive targets remain at least 48 dp; status is conveyed in words as well as color.
