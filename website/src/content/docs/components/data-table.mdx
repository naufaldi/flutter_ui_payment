`PaymentDataTable` displays host records with typed cells, selection, row actions and paging. Select-all covers the current page. On narrow screens and at large text, columns become labeled rows.

With local paging or no pagination, the table filters through a host predicate and sorts copies of the rows. With offset or cursor paging, it displays rows as supplied and calls the host when sorting or paging changes.

Batch actions sit beside the selection count when they fit; otherwise they move below it without wrapping their labels. Column reorder and resize are unsupported. Their deprecated flags must remain false until removal in 0.3.0.

## Usage

```dart
// example/lib/screens/gallery_content.dart
PaymentDataTable<int>(
          columns: columns,
          rows: const [],
          rowKey: (r) => '$r',
          pending: true,
        );
```

## Variants

<Screen name="android_tablet_catalog_data_table_variants" alt="Settlement table with search, selection, pagination, loading rows and an empty state; later examples extend beyond the 1200 dp crop cap, in English on Android tablet." caption="Wide (tablet)" />

Variants: text, link, date, id, status, currency cells; local, offset, cursor pages.

### States and content

Choose local paging for records already held by the app. With offset or cursor paging, supply the current page and handle page and sort callbacks in the host.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| Settlement selection and sort | local pages | Use offset/cursor callbacks for host pages; never reorder those rows locally. |

Use Table for static fees.

Choose paging by who holds the rows:

| Who holds the rows | Paging |
| --- | --- |
| The host supplied the complete list | Local paging |
| The host fetches one page at a time, with a numeric page position | Offset callbacks |
| The host fetches one page at a time, without a numeric position | Cursor callbacks |

## States

The host supplies loading, error and empty state, selected row IDs and paging data. For server paging, keep sorting and filtering on the server as well.

## Do and don't

**Do**: Use offset/cursor callbacks for host pages; never reorder those rows locally.

**Don't**: Enable deprecated column reorder or resize flags.

## Content guidelines

Use short column labels and explicit status words. Keep currency visible and references distinguishable from amounts.

## Accessibility

Narrow rows retain column context in semantics. Select-all names its page scope, and sorting announces the column and direction.

On phones, select-all has a visible label. The sort trigger names its column and direction; Default order restores host order.
