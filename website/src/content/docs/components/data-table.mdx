Settlement statements use host data. Variants: text, link, date, id, status, currency cells; local, offset, cursor pagination. Nothing else exists. Under local paging or no pagination, a host predicate filters rows and sortable columns reorder copies. Under offset/cursor paging, rows are displayed as supplied and sort/page changes call the host. Selection is controlled, and select-all covers the current page. Narrow and large-text layouts collapse to labeled rows. Column reorder/resize are deferred to Phase 6 and their flags must remain false. Stripe batchable maps to selection/onSelectionChanged; loading maps to pending; linkMap maps to column callbacks. No network or destination handling is performed.

## Usage

```dart
PaymentDataTable<String>(columns: [PaymentDataColumn<String>(key: "reference", label: "Reference", value: (row) => row)], rows: const ["STL-DEMO-1"], rowKey: (row) => row);
```

## States and content

The host supplies state and callbacks. Explain empty states and offer a next action. Use specific labels that wrap. Keep one primary action; separate destructive actions. Use semantic tokens and status text alongside visual marks.

## Accessibility

Labels wrap at large text. Controls retain their keyboard and screen-reader behavior. The host owns navigation and side effects.

On phones, select-all has a visible label. The sort trigger names its column and direction; Default order restores host order.
