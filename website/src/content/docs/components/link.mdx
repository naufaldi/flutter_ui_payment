Inline actions hug their label with a 48 dp target and no container. Primary uses an accent heading; secondary uses an underlined caption. External destinations have a trailing glyph, link role and spoken hint. In-place actions use the button role. The host opens the destination. Variants: primary, secondary. Nothing else exists.

## Usage

```dart
// example/lib/screens/gallery_selection.dart
PaymentLink(label: 'Edit', onPressed: null);
```

## Stripe → kit

| Source | Kit |
| --- | --- |
| children | label or icon |
| disabled | onPressed: null (icon and link) |
| onPress | onPressed, or host onCopy for copy |
| external / href / target / rel | external visual/semantics; host callback owns destination |
| type | variant where supported |

Width and alignment follow content. Host widgets own keyboard ordering and platform services. Do use a clear action name; avoid unlabeled glyphs and button-like containers for links.

## Variants

Variants: primary, secondary. Nothing else exists.

Use Button for the main task action.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: Use a host callback and external indicator for a destination outside the app.

**Don't**: Put navigation or URL-opening implementation inside the kit.

## Content guidelines

Use sentence case and name the payment fact or action. Keep instructions visible and use semantic type, color and spacing tokens.

Use a host callback and external indicator for a destination outside the app.

## Accessibility

Targets are at least 48 dp. Tooltips name icon actions. Links announce their role and external destinations. Copy feedback uses a live region and a check rather than color alone.
