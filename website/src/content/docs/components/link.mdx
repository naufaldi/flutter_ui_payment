Inline actions hug their label with a 48 dp target and no container. Primary uses an underlined accent heading; secondary uses an underlined caption. The underline marks a link even when the accent is monochrome and matches heading text. External destinations have a trailing glyph, link role and spoken hint. In-place actions use the button role. The host opens the destination. Variants: primary, secondary.

## Usage

```dart
// example/lib/screens/gallery_selection.dart
PaymentLink(label: 'Edit', onPressed: null);
```

## Stripe → kit

| Source | Kit |
| --- | --- |
| children | label or icon |
| disabled | onPressed: null (icon and link) |
| onPress | onPressed, or host onCopy for copy |
| external / href / target / rel | external visual/semantics; host callback owns destination |
| type | variant where supported |

Width and alignment follow content. Host widgets own keyboard ordering and platform services. Do use a clear action name; avoid unlabeled glyphs and button-like containers for links.

## Variants

Variants: primary, secondary.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| Merchant support destination | secondary | Use a host callback and external indicator for a destination outside the app. |

Use Button for the main task action.

## States

The host handles the destination or in-place action. A disabled link keeps its label visible and cannot be activated.

## Do and don't

**Do**: Use a host callback and external indicator for a destination outside the app.

**Don't**: Put navigation or URL-opening implementation inside the kit.

## Content guidelines

Use a destination or action as the label, such as "View statement". Mark external destinations so the person knows they are leaving the app.

## Accessibility

Targets are at least 48 dp. Tooltips name icon actions. Links announce their role and external destinations. Copy feedback uses a live region and a check rather than color alone.
