`showPaymentConfirmDialog` asks a yes-or-no question before an action that cannot be undone, and returns a `Future<bool>`.

<HostOwns>the action itself, which you run only after the dialog resolves to true.</HostOwns>



On a phone the confirmation is a bottom sheet; on a wider window it is a centred dialog (D45). The page keeps the name "Dialog".

## Usage

```dart
// example/lib/screens/gallery_kit.dart
showPaymentConfirmDialog(
      context,
      title: _t(
        context,
        'Sign out of all devices?',
        'Keluar dari semua perangkat?',
      ),
      message: _t(
        context,
        'You will need to sign in again on every device. Payments already sent are not affected.',
        'Anda perlu masuk lagi di setiap perangkat. Pembayaran yang sudah dikirim tidak terpengaruh.',
      ),
      confirmLabel: _t(context, 'Sign out', 'Keluar'),
      destructive: true,
    );
```

## Variants

Variants: ordinary confirm, destructive confirm. Nothing else exists.

### Result

The future resolves to `true` only when the person presses the confirm button. Cancel, tapping the scrim, Back and Escape all resolve to `false`.

### Default

The confirm button is filled with the accent and the cancel button is a quiet text button. The confirm button receives focus first.

### Destructive

`destructive: true` fills the confirm button in the danger tone, the same colors as a [destructive button](/components/button/#destructive), and moves first focus to the cancel button, so Enter never confirms by accident.

### Custom cancel label

The cancel button says "Cancel" by default. Pass `cancelLabel` when the safe choice reads better as an action of its own, such as "Keep paying".

### Phone: confirm sheet

Below 600 dp the confirmation slides up as a bottom sheet with no drag handle: the title, then the message, then the actions. The actions are stacked top-down at full width with centred labels, the confirm action on top and a quiet Cancel below. One 16 dp inset holds on every edge at every text scale, plus the bottom safe area. Language and text size never change the layout, so English, Indonesian and 200% text all look the same. At large text the title and message scroll, and the actions stay on screen.

### Wide: centred dialog

At 600 dp and wider the confirmation is a centred dialog, at most 400 dp wide, with the same 16 dp edges. The actions are one row of equal-width buttons with Cancel first and the confirm action trailing.

### Dismiss paths

| Path | Phone sheet | Wide dialog | Result |
| --- | --- | --- | --- |
| Confirm button | yes | yes | `true` |
| Cancel button | yes | yes | `false` |
| Scrim tap | yes | yes | `false` |
| Swipe down | yes | — | `false` |
| Back | yes | yes | `false` |
| Escape | yes | yes | `false` |
| Enter | activates the focused button | activates the focused button | `true` only when the confirm action has focus |

### Actions and focus

Cancel is quiet; Confirm is primary or destructive. Keyboard focus uses the neutral ring, starting on Cancel for destructive actions and on Confirm otherwise. Enter activates that safe initial choice. Opening a confirmation from inside a sheet, such as the focus view's discard question, stacks a sheet on the sheet. That is expected.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: Name the consequence and keep Cancel quiet; focus Cancel for destruction.

**Don't**: Ask for confirmation before every reversible interaction.

## Content guidelines

- Ask the question in the title: "Remove this card?", "Sign out of all devices?".
- Use the message for the consequence, and for what is not affected: "Payments already sent are not affected."
- Make `confirmLabel` repeat the action: "Sign out", "Remove card". Never "Yes" or "OK".
- Do not use a dialog to cancel a payment by itself. A cancel request goes to your host, and the payment stays pending until your host decides; see [Sheet](/components/sheets/).

Name the consequence and keep Cancel quiet; focus Cancel for destruction.

## Accessibility

Preserve reading order, visible labels and semantic descriptions. Interactive targets remain at least 48 dp; status is conveyed in words as well as color.
