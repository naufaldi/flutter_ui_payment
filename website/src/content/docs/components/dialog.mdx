`showPaymentConfirmDialog` asks a yes-or-no question before an action that cannot be undone, and returns a `Future<bool>`.

Run the action only after the dialog resolves to `true`.

On a phone the confirmation is a bottom sheet; on a wider window it is a centred dialog. The page keeps the name "Dialog".

## Usage

### Minimal

Add the [published package](/start/installation/), then paste this complete example into `lib/main.dart`.

```dart standalone
import 'package:flutter/material.dart';
import 'package:rakit_ui/rakit_ui.dart';

void main() => runApp(MaterialApp(
  home: Scaffold(
    appBar: AppBar(title: const Text('Example')),
    body: Builder(builder: (context) => Padding(
      padding: const EdgeInsets.all(16),
      child: PaymentButton(
        label: 'Archive note',
        variant: PaymentButtonVariant.secondary,
        onPressed: () async {
          final confirmed = await showPaymentConfirmDialog(
            context,
            title: 'Archive this note?',
            message: 'You can restore it later.',
            confirmLabel: 'Archive',
          );
          if (!context.mounted || !confirmed) return;
          ScaffoldMessenger.of(context).showSnackBar(
            const SnackBar(content: Text('Archive confirmed')),
          );
        },
      ),
    )),
  ),
));
```

## Variants

Variants: ordinary confirm, destructive confirm.

### Result

The future resolves to `true` only when the person presses the confirm button. Cancel, tapping the scrim, Back and Escape all resolve to `false`.

### Default

The confirm button is filled with the accent and the cancel button is a quiet text button. The confirm button receives focus first.

### Destructive

`destructive: true` fills the confirm button in the danger tone, the same colors as a [destructive button](/components/button/#destructive), and moves first focus to the cancel button, so Enter never confirms by accident.

### Custom cancel label

The cancel button says "Cancel" by default. Pass `cancelLabel` when the safe choice reads better as an action of its own, such as "Keep paying".

### Phone: confirm sheet

On a phone, when the window's shorter side is under 600 dp, the confirmation slides up as a bottom sheet with no drag handle: the title, then the message, then the actions. The actions are stacked top-down at full width with centred labels, the confirm action on top and a quiet Cancel below. One 16 dp inset holds on every edge at every text scale, plus the bottom safe area. Language and text size never change the layout, so English, Indonesian and 200% text all look the same. At large text the title and message scroll, and the actions stay on screen. A phone held sideways (640 × 360 dp) keeps this sheet.

### Wide: centred dialog

On a tablet, with a shorter side of 600 dp or more, the confirmation is a centred dialog, at most 400 dp wide, with the same 16 dp edges. The actions are one row of equal-width buttons with Cancel first and the confirm action trailing.

### Dismiss paths

| Path | Phone sheet | Wide dialog | Result |
| --- | --- | --- | --- |
| Confirm button | yes | yes | `true` |
| Cancel button | yes | yes | `false` |
| Scrim tap | yes | yes | `false` |
| Swipe down | yes | — | `false` |
| Back | yes | yes | `false` |
| Escape | yes | yes | `false` |
| Enter | activates the focused button | activates the focused button | `true` only when the confirm action has focus |

### Actions and focus

Cancel is quiet; Confirm is primary or destructive. Keyboard focus uses the neutral ring, starting on Cancel for destructive actions and on Confirm otherwise. Enter activates that safe initial choice. Opening a confirmation from inside a sheet, such as the focus view's discard question, stacks a sheet on the sheet. That is expected.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| Discard report | destructive confirm | Name the consequence and keep Cancel quiet; focus Cancel for destruction. |

Use Focus view for collecting a report.

## States

Confirm resolves to `true`. Cancel, Back, Escape and scrim dismissal resolve to `false`; the host performs the confirmed operation.

## Do and don't

**Do**: Name the consequence and keep Cancel quiet; focus Cancel for destruction.

**Don't**: Ask for confirmation before every reversible interaction.

## Content guidelines

- Ask the question in the title: "Remove this card?", "Sign out of all devices?".
- Use the message for the consequence, and for what is not affected: "Payments already sent are not affected."
- Make `confirmLabel` repeat the action: "Sign out", "Remove card". Never "Yes" or "OK".
- Do not use a dialog to cancel a payment by itself. A cancel request goes to your host, and the payment stays pending until your host decides; see [Sheet](/components/sheets/).

## Accessibility

Initial focus is on Cancel for destructive actions and Confirm otherwise. Dismissal returns `false`; labels and messages remain readable at large text.
