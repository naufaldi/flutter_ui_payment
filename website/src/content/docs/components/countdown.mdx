## Variants

Variants: remaining, warning, elapsed. Nothing else exists.

### When the deadline passes

The countdown stops at `00:00` and never goes negative. `onElapsed` is called once, after the frame, including when the deadline has already passed the first time the widget builds. Changing `expiresAt` starts a new countdown, and `onElapsed` can fire again for the new deadline.

Use `onElapsed` to ask your host for the status, not to show "expired". A transfer made in the last second may still arrive.

### Formatting outside the widget

The static helpers do the same arithmetic without a widget:

```dart
final left = CountdownText.remaining(va.expiresAt, host.clock());
final text = CountdownText.formatDuration(left); // "14:59"
```

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

**Layout.** The countdown reserves the width of the longest format it will show, so the text does not jump when 1:00:00 becomes 59:59.

## Do and don't

**Do**: Pass the host expiry and clock; elapsed is a display state, not a payment verdict.

**Don't**: Infer payment failure from an elapsed timer.

## Content guidelines

- Pair the countdown with the deadline itself (a date and time) so the person can plan, as the virtual account instructions do.
- Label it with what the deadline is for: "Pay before", not "Timer".

Pass the host expiry and clock; elapsed is a display state, not a payment verdict.

## Accessibility

- Digits are tabular, so the width does not change as they tick.
- Screen readers hear "Time remaining 14:59" (or the Indonesian equivalent).
- The countdown is never animated beyond its once-a-second text change.
