`PaymentTable` presents host-provided payment facts. The host computes amounts and owns every action.

## Usage

```dart
// example/lib/screens/steps/fees_step.dart
PaymentTable(
            caption: s.feesTitle,
            head: const [
              PaymentTableHeaderCell('Method', rowHeader: true),
              PaymentTableHeaderCell('Fee', numeric: true),
              PaymentTableHeaderCell('Arrives'),
            ],
            rows: [
              for (final (method, fee, arrives) in [
                ('Virtual account', 2500, 'Within 10 min'),
                ('QRIS', 0, 'Instant'),
                ('Ruang Bayar balance', 0, 'Instant'),
                ('Card', 4000, 'Instant'),
              ])
                PaymentTableRow([
                  PaymentTableCell(Text(method)),
                  PaymentTableCell(AmountText(Money.idr(fee)), numeric: true),
                  PaymentTableCell(Text(arrives)),
                ]),
            ],
          );
```

## Variants

Variants: wide table, narrow labeled rows. Nothing else exists.

Use for fee schedules or host-computed statement summaries. Below 600 dp or at large text, rows become labeled lists. Wide tables pin the row-header column and scroll other columns with an edge fade. Numeric columns align to the end with tabular figures. No stripes. Spans, centered columns, and arbitrary cell widths are not supported.

### Content and accessibility

Use short, descriptive labels. Labels and narrow values wrap. Do show the currency beside an amount. Do not use color alone to communicate a result. Headings carry header semantics; facts merge their label and value. Wide table cells repeat their column label for assistive technology. Totals are computed by the host.

A04 is a static fee schedule with tabular amounts, phone row collapse and contextual fee help.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| Fee comparison | wide table | Keep amounts numeric and method as the row header; phones collapse automatically. |

Use Data table for settlement selection and paging.

## States

Static rows collapse into labeled list rows below 600 dp or at large text. Loading, empty and error presentation belongs to the surrounding host page.

## Do and don't

**Do**: Keep amounts numeric and method as the row header; phones collapse automatically.

**Don't**: Add paging/selection controls around a static fee schedule.

## Content guidelines

Use sentence case and name the payment fact or action. Keep instructions visible and use semantic type, color and spacing tokens.

Keep amounts numeric and method as the row header; phones collapse automatically.

## Accessibility

Preserve reading order, visible labels and semantic descriptions. Interactive targets remain at least 48 dp; status is conveyed in words as well as color.
