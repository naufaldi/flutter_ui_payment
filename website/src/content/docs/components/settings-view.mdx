Group payment preferences with PaymentFormFieldGroup sections such as Notifications, Payments and Language. Do not use one flat list. Save is the primary action and locks repeat taps while its Future runs. The host owns values, persistence and statusMessage; status is announced in the header. Avoid another primary action in child.

## Usage

```dart
// example/lib/screens/gallery_views.dart
PaymentSettingsView(
        title: 'Payment settings',
        statusMessage: 'Saved',
        statusTone: StatusTone.success,
        onSave: () async {
          await Future<void>.delayed(const Duration(milliseconds: 600));
        },
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          spacing: PaymentTheme.of(context).space(PaymentSpace.block),
          children: [
            PaymentFormFieldGroup(
              legend: 'Notifications',
              children: [
                PaymentSwitch(
                  label: 'Refund notifications',
                  value: refunds,
                  onChanged: (v) => setState(() => refunds = v),
                ),
                PaymentSwitch(
                  label: 'Promotions',
                  value: promos,
                  onChanged: (v) => setState(() => promos = v),
                ),
              ],
            ),
            PaymentFormFieldGroup(
              legend: 'Default method',
              children: [
                for (final value in ['bank', 'wallet'])
                  PaymentRadio<String>(
                    value: value,
                    groupValue: method,
                    onChanged: (v) => setState(() => method = v),
                    label: value == 'bank' ? 'BCA virtual account' : 'Wallet',
                  ),
              ],
            ),
            PaymentFormFieldGroup(
              legend: 'Language',
              children: [
                PaymentSelect<String>(
                  label: 'Statement language',
                  options: const [
                    PaymentSelectOption(value: 'en', label: 'English'),
                    PaymentSelectOption(value: 'id', label: 'Bahasa Indonesia'),
                  ],
                  value: language,
                  onChanged: (v) => setState(() => language = v),
                ),
              ],
            ),
          ],
        ),
      );
```

## Variants

Variants: idle, saving, saved, error. Nothing else exists.

### States and content

The host supplies state and callbacks. Explain empty states and offer a next action. Use specific labels that wrap. Keep one primary action; separate destructive actions. Use semantic tokens and status text alongside visual marks.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| Account preferences | idle | Group Notifications, Payments and Language; Save is the only primary action. |

Use Full page view for read-only account facts.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: Group Notifications, Payments and Language; Save is the only primary action.

**Don't**: Keep old Saved feedback after the customer edits a setting.

## Content guidelines

Use sentence case and name the payment fact or action. Keep instructions visible and use semantic type, color and spacing tokens.

Group Notifications, Payments and Language; Save is the only primary action.

## Accessibility

Labels wrap at large text. Controls retain their keyboard and screen-reader behavior. The host owns navigation and side effects.

Save fills the phone footer and hugs the end on wide layouts. The host supplies the save result.

A05 groups Notifications, Payments and Language. Save is the sole primary action; failure supports retry, and editing clears stale save feedback.
