`PaymentSwitch` turns a setting on or off immediately, such as "Refund alerts". The switch sits at the end of the row, and the whole row is the target.

## Usage

```dart
// example/lib/screens/gallery_selection.dart
PaymentSwitch(
              value: _sms,
              onChanged: (v) => setState(() => _sms = v),
              label: 'SMS receipts',
            );
```

## Variants

Variants: off, on. Nothing else exists.

### Switch or checkbox

Use a switch when the change applies the moment it is flipped, like a setting. Use a [checkbox](/components/checkbox/) when the choice is only applied after a button press, such as "Save this card" before paying.

### On and off

When on, the track fills with the accent and the thumb moves to the end and shows a check. When off, the track is the surface with a `border` edge. Position and the check carry the state, so it is never color alone.

### Disabled

Pass `onChanged: null`. The track turns `surfaceMuted`, the label turns muted, and taps do nothing. Pass `disabledReason`; it replaces `description` while the row is disabled.

```dart
const PaymentSwitch(
  value: false,
  onChanged: null,
  label: 'Weekly summary',
  disabledReason: 'Turn on notifications in Settings',
);
```

### Behavior, states and migration

Stripe error maps to errorText: icon, danger caption and off-track danger edge. Required is spoken, with gating owned by the host. HiddenElements retains hidden text in semantics. Use a switch for an immediate setting, not consent applied after a later submit.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: Use for independent persistent preferences, with the label centered to the mark.

**Don't**: Use a switch to start a one-time payment action.

## Content guidelines

- Name the setting, not the action: "Refund alerts", not "Turn on refund alerts".
- Use the description for what the setting does when on.
- If applying the setting can fail, show the switch in its old position and tell people with a [toast](/components/toast/).

Use for independent persistent preferences, with the label centered to the mark.

## Accessibility

- The whole row is one target and one screen-reader node, announced as a toggle that is on or off.
- The painted switch takes no focus of its own; one Tab reaches the row. Keyboard focus draws the kit's [focus ring](/foundations/focus/).

The switch mark centers on the first label line; the row retains its minimum touch target.
