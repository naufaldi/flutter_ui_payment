`PaymentButton` starts an action. When `onPressed` returns a Future, the button shows a busy state and ignores more taps until it completes, so a double tap sends one callback.

## Usage

```dart
// example/lib/screens/gallery_content.dart
PaymentButton(label: 'Check status', onPressed: () {});
```

## Stripe → kit

| Stripe prop | Kit | Note |
| --- | --- | --- |
| label | label | Semantic kit value; see API for the default. |
| onAction | onPressed | Host callback owns the effect. |
| size | size | Semantic kit value; see API for the default. |

DOM-specific props are not mirrored: Flutter uses widget composition and host callbacks. See [Not in the kit](/reference/not-in-the-kit/).

## Variants

Variants: primary, secondary, quiet, destructive. Nothing else exists.

### Primary

The one main action on a screen: pay, continue, confirm. Filled with `accent`. Use one primary per screen.

```dart
PaymentButton(label: 'Continue', onPressed: next);
```

### Secondary

An alternative to the main action, such as "Change method". Outlined with the 3:1 `border` color.

```dart
PaymentButton(
  label: 'Change method',
  variant: PaymentButtonVariant.secondary,
  onPressed: openMethods,
);
```

### Quiet

A low-emphasis action such as "Not now" or "Cancel": text only.

A quiet button that hugs its label is a text action, like a [link](/components/link/): its text starts on the column edge, and its box (the press and focus state) hangs outward by its padding, at most 12 dp, into the gutter. Inside a row's trailing slot the text sits on the end edge instead. In a [button group](/components/button-group/), and when it fills the width (footers, confirm sheets), its label stays centred (#65). Put quiet buttons that sit side by side in a `PaymentButtonGroup` rather than your own `Row`.

```dart
PaymentButton(
  label: 'Not now',
  variant: PaymentButtonVariant.quiet,
  onPressed: dismiss,
);
```

### Destructive

An action that cannot be undone, such as removing a saved card. Filled in the danger tone with the surface color for the label, the same colors as the confirm button of a destructive [dialog](/components/dialog/). The label must say what happens, so color is never the only signal. Ask first with `showPaymentConfirmDialog` where the action matters, and never use it for the pay button.

```dart
PaymentButton(
  label: 'Remove card',
  icon: Icons.delete_outline,
  variant: PaymentButtonVariant.destructive,
  onPressed: () async {
    final ok = await showPaymentConfirmDialog(
      context,
      title: 'Remove this card?',
      message: 'You can add it again later.',
      confirmLabel: 'Remove card',
      destructive: true,
    );
    if (ok) await host.removeCard(card.id);
  },
);
```

### One primary per surface

A screen, sheet or dialog has at most one primary button: its completion action (D54). A button that only opens another surface, such as "Open sheet", is secondary, and the sheet's own "Done" is primary. Use equal-weight secondaries only for peer alternatives with no default, such as Share and Download.

### No warning button

There is no warning variant (D47). A warning is a state, so show it with a [banner](/components/banner/), a [badge](/components/badge/) or a [toast](/components/toast/) next to the action. The button's label says what happens.

### Busy

A button is busy while the Future from `onPressed` runs, or while you pass `busy: true` for an action you run elsewhere, such as a submit your coordinator owns. The label keeps its space so the layout does not jump, a [spinner](/components/spinner/) takes its place, and screen readers hear `busyLabel` (default "Working…"). Under reduced motion the spinner is a still hourglass.

```dart
PaymentButton(
  label: 'Pay Rp102.500',
  busy: coordinator.submitting,
  busyLabel: 'Sending payment',
  onPressed: coordinator.submit,
);
```

### Disabled

Pass `onPressed: null`. Every variant uses the `disabled` label color; the filled and outlined variants also turn `surfaceMuted`. Tell people why nearby, for example with a caption under the button, because a disabled button cannot explain itself.

### With an icon

`icon` puts a 16 px icon in small buttons and a 20 px icon in medium and large buttons before the label. In medium and large buttons it grows with the text up to 32 px at 200%. When the label wraps at large text, the icon sits beside its first line and the two stay centred together (D56). Use it when the icon adds meaning (delete, download), not as decoration on every button.

### Sizes and widths

Variants: primary, secondary, quiet, destructive. Nothing else exists.

| Size | Visual height | Horizontal padding at 100% | Icon / busy spinner |
| --- | --- | --- | --- |
| small | 36 dp | 12 dp | 16 dp |
| medium (default) | 48 dp | Material default: 24 dp; quiet 12 dp | 20 dp |
| large | 56 dp | 24 dp | 20 dp |

Every size occupies a hit box of at least 48 × 48 dp. The small visual is centered inside it; the keyboard ring follows the visual. Use small for a module-header action such as Add card. Keep the main Pay action medium or large. Material density is pinned to standard, so medium buttons draw at 48 dp. Product targets are iOS and Android phones and tablets (D64).

`width: PaymentWidth.fill` fills the parent by default. `PaymentWidth.hug` sizes to the label with a 112 dp minimum; a quiet hug button outside a button group hugs its label with only the 48 dp floor, so its text can start on the column edge. Put hug buttons inside an Align or Wrap; a stretching parent overrides hug. Long labels wrap and never truncate.

`autofocus` focuses the action when its route opens. Focus Cancel in a destructive confirmation; focus Confirm for an ordinary confirmation.

| Stripe | Kit |
| --- | --- |
| primary | primary for the one next action |
| secondary | secondary for a supporting action |
| tertiary | quiet for dismissing or deferring |
| destructive | destructive only when confirming the named consequence |

The documentation specimen intentionally shows multiple primary states together. Product views keep one primary action.

focusNode supports host focus return, including custom menu triggers.

[Button group](/components/button-group/) now composes related status and dialog actions. Overflow menus wrap long labels at large text.

## Width (D59, D59a, D62)

| Where the button sits | On phones | Wide |
| --- | --- | --- |
| Footer of a view or page, sheet, confirm dialog: the action that finishes or advances the task | Full width, primary on top, at most one quiet action under it | Hug, at the end edge |
| Page header | Not a button: one action is a title-row link "Label ›", more go behind ⋮ | Hug |
| Rows, cards, banners, state messages, tables | Hug | Hug |

The screen's priority action pins at the bottom (D62); a full-width button in a header would read as the main step and push the content down.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: One primary per view; supporting receipt/report actions are secondary; Cancel is quiet.

**Don't**: Put two primary buttons in one product view.

## Content guidelines

- Start with a verb and say what happens: "Pay Rp102.500", "Remove card", "Check status". Avoid "OK" and "Submit".
- Put the amount in the pay button, formatted with `MoneyFormat`, so the button and the summary agree.
- Use sentence case and no end punctuation.
- Keep labels short enough for one line at normal text size. At large text they wrap rather than truncate.
- A destructive label names the thing it destroys: "Remove card", not "Remove".

One primary per view; supporting receipt/report actions are secondary; Cancel is quiet.

## Accessibility

- 48 dp minimum height. Keyboard focus draws the kit's [focus ring](/foundations/focus/), never the brand color.
- Full-width buttons do not scale on press; Material's pressed layer is the feedback.
- While busy, the button is a live region that announces `busyLabel`.
