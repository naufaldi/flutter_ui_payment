## Usage and Stripe → kit

```dart
PaymentSelect<String>(label: 'Occupation', options: const [PaymentSelectOption(value: 'employee', label: 'Employee')], value: occupation, onChanged: onOccupationChanged);
```

| Stripe | Kit |
| --- | --- |
| value / onChange | value / onChanged |
| multiple | PaymentSelect.multiple |
| disabled | onChanged: null |


Single selection uses radios and closes on a changed choice. Multiple selection uses draft checkboxes and Apply. Seven or more options add a local filter. Disabled choices explain why. Focus returns to the trigger. Re-tapping the selected radio leaves the sheet open. validator integrates with Form; focusNode supports focusing the first error. Fields fill; css width, autoComplete, name and form are not mirrored.

## Which variant when

Use these fields for a bounded task. Use the host validator for business rules and persistent descriptions for instructions.

## States

Default, focused, disabled and error. Errors include an icon, text and an edge. Selection controls support hardware keyboards.

## Do and don't

Keep labels visible. Avoid placing the only instruction in a hint.

## Content guidelines

Use short, specific labels and explain how to correct an error.

## Accessibility

Input text is 16 dp. Legends precede fields in reading order. Labels and errors stay in semantics when visually hidden. Pickers restore focus.
