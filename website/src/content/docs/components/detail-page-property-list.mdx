Transaction facts with optional linked values and subText. Variants: vertical, horizontal; pending, ready, empty, error. Values are `PaymentDetailValue` text or links with optional subText; extra actions are links in an overflow menu. A failed module uses warning tone because it is secondary content. Your app handles retry, Create and link destinations. Empty messages explain why and offer an action.

## Usage

```dart
// example/lib/screens/gallery_views.dart
PaymentDetailPagePropertyList(
            title: 'Merchant',
            pending: false,
            items: [
              const PaymentDetailProperty(
                label: 'Name',
                values: [PaymentDetailValue('Toko Contoh')],
              ),
              PaymentDetailProperty(
                label: 'Support',
                values: [
                  PaymentDetailValue.link(
                    PaymentLink(
                      label: 'Help centre',
                      external: true,
                      onPressed: () {},
                    ),
                  ),
                ],
              ),
            ],
          );
```

## Variants

Variants: vertical, horizontal; pending, ready, empty, error.

### States and content

Choose vertical for longer facts and horizontal for short values that fit beside their labels. Narrow and large-text layouts stack the content.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| Merchant facts | vertical | Use a link-only value for support; place the module directly in DetailPage. |

Use Detail page table for repeated attempts.

## States

Use pending while facts load, an empty message when none are available, and a warning with retry when this supporting module fails.

## Do and don't

**Do**: Use a link-only value for support; place the module directly in DetailPage.

**Don't**: Wrap a titled property module in another titled module.

## Content guidelines

Use labels such as "Merchant" and "Reference". Keep linked values descriptive and unavailable facts distinct from empty strings.

## Accessibility

Keep fact labels with their values. Linked values and overflow actions need descriptive labels.

A single link-only value centers with its label; at large text it wraps.
