`PaymentPropertyList` presents host-provided payment facts. The host computes amounts and owns every action.

## Usage

```dart
// example/lib/screens/gallery_views.dart
PaymentPropertyList(items: facts);
```

## Stripe → kit

| Stripe | Kit |
| --- | --- |
| PropertyList | `PaymentPropertyList` |
| PropertyListItem | `PaymentPropertyListItem` |

## Variants

Variants: vertical, horizontal. Nothing else exists.

Use vertical for receipt and status details; horizontal for a few short summary facts. Horizontal facts stack below 360 dp or at large text. Nested property lists are not supported.

### Content and accessibility

Use short, descriptive labels. Labels and narrow values wrap. Do show the currency beside an amount. Do not use color alone to communicate a result. Headings carry header semantics; facts merge their label and value. Wide table cells repeat their column label for assistive technology. Totals are computed by the host.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| Sign-in data-sharing explanation | vertical | Use horizontal only for short facts that fit; narrow/large text stacks. |

Use Table for records with shared columns.

## States

The host supplies ready values. Use `LoadingSkeleton.table` for loading and `StateMessage` for an empty or failed load. Empty states should explain why and offer a next action.

## Do and don't

**Do**: Use horizontal only for short facts that fit; narrow/large text stacks.

**Don't**: Use a property list to simulate selectable ledger rows.

## Content guidelines

Use sentence case and name the payment fact or action. Keep instructions visible and use semantic type, color and spacing tokens.

Use horizontal only for short facts that fit; narrow/large text stacks.

## Accessibility

Preserve reading order, visible labels and semantic descriptions. Interactive targets remain at least 48 dp; status is conveyed in words as well as color.
