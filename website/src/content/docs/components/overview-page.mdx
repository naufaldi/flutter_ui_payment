A spending overview composes flat ruled modules. Variants: single column, primary/secondary columns at 840 dp. Nothing else exists. OverviewPage never scrolls vertically; place it in FullPageView or an existing host scroll region. Module actions are small hug buttons; extra actions collapse into a menu.

## Usage

```dart
// example/lib/screens/gallery_views.dart
PaymentOverviewPage(
          primary: [
            ChartModule(
              title: 'This month',
              state: ChartState.ready,
              chart: SizedBox(
                height: 240,
                child: PaymentBarChart(points: _chartFixture('typical')),
              ),
            ),
            const PaymentPageModule(
              title: 'Recent transactions',
              child: PaymentPropertyList(
                items: [
                  PaymentPropertyListItem(
                    label: 'Toko Contoh',
                    valueText: 'Rp102.500',
                  ),
                  PaymentPropertyListItem(
                    label: 'Groceries',
                    valueText: 'Rp75.000',
                  ),
                  PaymentPropertyListItem(
                    label: 'Coffee',
                    valueText: 'Rp25.000',
                  ),
                ],
              ),
            ),
          ],
          secondary: const [
            PaymentPageModule(
              title: 'Balance',
              child: PaymentPropertyList(
                items: [
                  PaymentPropertyListItem(
                    label: 'Available',
                    valueText: 'Rp500.000',
                  ),
                ],
              ),
            ),
          ],
        );
```

## Spacing and width

Modules are spaced evenly: a chart module gets the same space under it as a page module (24 dp to the next module's hairline). Inside a view, one column is capped at 640 dp; with a secondary column the page keeps two columns from 840 dp, capped at 1040 dp (D53). Give a chart module the headline it summarises; a "—" beside a chart with data reads as missing.

## Variants

Variants: single column, primary/secondary columns. Nothing else exists.

### States and content

The host supplies state and callbacks. Explain empty states and offer a next action. Use specific labels that wrap. Keep one primary action; separate destructive actions. Use semantic tokens and status text alongside visual marks.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| Spending and monthly facts | primary/secondary columns | Place ChartModule directly in primary and facts directly in secondary. |

Use Detail page for a transaction destination.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: Place ChartModule directly in primary and facts directly in secondary.

**Don't**: Add a second scroll region inside FullPageView.

## Content guidelines

Use sentence case and name the payment fact or action. Keep instructions visible and use semantic type, color and spacing tokens.

Place ChartModule directly in primary and facts directly in secondary.

## Accessibility

Labels wrap at large text. Controls retain their keyboard and screen-reader behavior. The host owns navigation and side effects.

Primary and secondary accept page modules, detail property lists, detail tables and chart modules directly. Arbitrary body widgets fail the debug admission check.
