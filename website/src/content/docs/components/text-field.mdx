## Stripe → kit

| Stripe | Kit |
| --- | --- |
| label | label |
| placeholder | hint |
| description | description, descriptionTone |
| error / invalid | errorText / derived from validation |
| required / hiddenElements | required / hiddenElements |
| size / type | size / type, with no sensitive input types |
| defaultValue | initialValue |
| value / onChange | controller / onChanged |
| disabled / readOnly | enabled / readOnly |
| spellCheck / autoComplete | type traits / autofillHints |

Autofocus is omitted because touch keyboards should be requested deliberately through a focus node. Host forms own names, ordering and keyboard handlers. Use input formatters for length constraints and validators for meaning. Width is deferred until field groups define it. `keyboardType` preserves custom host keyboards, including dates.

## Variants

Variants: text, number, tel, url, email, search; small, medium, large. Nothing else exists.

### Which variant

Use a general field for names and addresses, reference typography for identifiers, a currency field for money parsing, and `.search` for immediate local filtering. Remote search debounce belongs to the host.

Variants: `type` × `size`, `reference`, `.search`. Nothing else exists.

### Content and accessibility

Keep a persistent label. Never put the only instruction in `hint`. Explain how to fix an error. Every size uses 16 px input text; padding varies without shrinking text. Hidden labels, descriptions and errors remain spoken. Required is semantic; the host must enforce it. Clearing search reports an empty query and refocuses the field. `.search(actions: …)` puts filter controls, such as a calendar `PaymentIconButton`, after the box on the same line, centred on the box; at large text the label above spans them. `.search(hiddenElements: {PaymentFieldPart.label})` shows the label as the placeholder instead, and the label stays the field's spoken name (`TransactionHistory` does this when it has `searchActions`, D63a).

### Field foundation

Fields fill their parent. Stripe css width is not mirrored. PaymentFormFieldGroup adds optional marks when required and optional fields are mixed. Use [Text area](/components/text-area/) for several lines.

Labels at large text: an outlined floating label keeps one line, so above 1.5× text every field (text, currency, date, select and search) shows its label above the box instead, where it wraps (#73). The box keeps its height, so fields of different types still line up, and the label stays the field's spoken name. While the label is above, the hint shows only when the field has focus, as it does behind a floating label. Keep labels short anyway and put instructions in description.

```text
What does the value mean?
├─ Filter visible records → search
├─ Numeric input → number
├─ Phone / destination / email → tel / url / email
└─ Other non-secret single-line value → text
```

## States

Default uses a border edge; focus uses a 2 px accent edge. Errors show an icon, message and danger edge, 2 px when focused. Disabled fields use disabled text and edge. Read-only retains default styling. Host errors hide after edits and return when the host passes a new error; pass null between identical attempts. Form validation timing belongs to the enclosing Form.

**Layout.** Small, medium and large fields are 48, 56 and 64 dp tall, and the text starts 16 dp in from the border at every size. Text, currency, date and select fields share these heights, so fields side by side line up.

## Do and don't

**Do**: Use search for list filtering; labels persist after entry.

**Don't**: Collect PIN, OTP, password or card secrets.

## Content guidelines

Use sentence case and name the payment fact or action. Keep instructions visible and use semantic type, color and spacing tokens.

Use search for list filtering; labels persist after entry.

## Accessibility

Preserve reading order, visible labels and semantic descriptions. Interactive targets remain at least 48 dp; status is conveyed in words as well as color.
