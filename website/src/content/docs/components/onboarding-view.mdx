KYC setup gets to current-step value first on phones, with all tasks in a collapsed accordion. At 840 dp a 280 dp task sidebar accompanies the current content. Variants: ready, pending, error, completed. Nothing else exists. The host owns every task status. onCompleted fires post-frame once when completed turns true, including an initially completed view; there is no timer or kit navigation.

**Pinned step action (D62).** `primaryAction`, with at most one quiet `secondaryAction`, is the current step's submit. Given a bounded height the content scrolls and the actions pin to a footer above the bottom safe area, full width on phones; inside a scroll view they follow the content. The footer is hidden while `pending` or `completed`, when the step isn't shown. A step's form then leaves out its own button: `IdentityForm` takes an `IdentityFormController`, and `VerificationReview` takes `inlineSubmit: false` with `VerificationReview.submitButton`. See [Verification](/patterns/verification/).

## Usage

```dart
// example/lib/screens/gallery_views.dart
PaymentOnboardingView(
        title: 'Verify your identity',
        tasks: const [
          PaymentTaskListItem(
            title: 'Identity',
            status: PaymentTaskStatus.complete,
          ),
          PaymentTaskListItem(
            title: 'Documents',
            status: PaymentTaskStatus.inProgress,
            subTasks: [
              PaymentTaskListItem(
                title: 'KTP',
                status: PaymentTaskStatus.complete,
              ),
              PaymentTaskListItem(title: 'Selfie'),
            ],
          ),
          PaymentTaskListItem(title: 'Review'),
        ],
        pending: state == 1,
        error: state == 2
            ? const PaymentBanner(
                tone: StatusTone.warning,
                title: 'Documents need attention',
              )
            : null,
        completed: state == 3,
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          spacing: PaymentTheme.of(context).space(PaymentSpace.block),
          children: [
            const Text('Add your identity documents to get started.'),
            button('Continue', variant: PaymentButtonVariant.primary),
          ],
        ),
      );
```

## Variants

Variants: ready, pending, error, completed. Nothing else exists.

### States and content

The host supplies state and callbacks. Explain empty states and offer a next action. Use specific labels that wrap. Keep one primary action; separate destructive actions. Use semantic tokens and status text alongside visual marks.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| KYC details/documents/review | ready | The host supplies task status and decides completion; current content precedes tasks on phones. |

Use Sign-in view for the external sign-in action.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: The host supplies task status and decides completion; current content precedes tasks on phones.

**Don't**: Treat the status result as another data-entry task.

## Content guidelines

Use sentence case and name the payment fact or action. Keep instructions visible and use semantic type, color and spacing tokens.

The host supplies task status and decides completion; current content precedes tasks on phones.

## Accessibility

Labels wrap at large text. Controls retain their keyboard and screen-reader behavior. The host owns navigation and side effects.

Used in H04 and K01 for identity details, document fixtures and review. The host decides task states; consent and verification results remain separate steps.
