Host-owned KYC setup tasks. Variants: notStarted, inProgress, blocked, complete. Nothing else exists. Distinct marks and spoken status distinguish progress without relying on color. Complete tasks hide their child tasks. The host decides every status.

## Usage

```dart
// example/lib/screens/gallery_content.dart
PaymentTaskList(
          items: [
            PaymentTaskListItem(
              title: 'Identity',
              status: PaymentTaskStatus.complete,
            ),
            PaymentTaskListItem(
              title: 'Documents',
              status: PaymentTaskStatus.inProgress,
              subTasks: [
                PaymentTaskListItem(
                  title: 'KTP',
                  status: PaymentTaskStatus.complete,
                ),
                PaymentTaskListItem(title: 'Selfie'),
              ],
            ),
            PaymentTaskListItem(
              title: 'Review',
              status: PaymentTaskStatus.blocked,
            ),
          ],
        );
```

## Variants

Variants: notStarted, inProgress, blocked, complete. Nothing else exists.

### States and content

The host supplies state and callbacks. Explain empty states and offer a next action. Use specific labels that wrap. Keep one primary action; separate destructive actions. Use semantic tokens and status text alongside visual marks.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| KYC progress | inProgress | The host decides status; completed steps may offer edit actions. |

Use Step indicator for a short linear merchant checkout sequence.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

## Do and don't

**Do**: The host decides status; completed steps may offer edit actions.

**Don't**: Mark a task complete just because its widget mounted.

## Content guidelines

Use sentence case and name the payment fact or action. Keep instructions visible and use semantic type, color and spacing tokens.

The host decides status; completed steps may offer edit actions.

## Accessibility

Labels wrap at large text. Controls retain their keyboard and screen-reader behavior. The host owns navigation and side effects.
