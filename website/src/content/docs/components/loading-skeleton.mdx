## Usage

```dart

LoadingSkeleton(rows: 3, leading: false);
```

## Stripe → kit

No Stripe equivalent. Admitted because: TransactionHistory A01; ChartModule; detail modules; this reusable payment composition keeps host state outside presentation.

## Variants

Variants: list, text block, table. Nothing else exists.

### Rows

`rows` sets how many placeholder rows are drawn (default 3). Match roughly how many rows usually appear, so the page does not jump much when the content arrives.

### Without leading squares

`leading: false` drops the square before each row, for content without icons.

```dart
const LoadingSkeleton(rows: 2, leading: false);
```

### Why it does not shimmer

The skeleton is static on purpose. A shimmer repaints every frame for as long as the load takes and says nothing a still placeholder does not.

## States

Host state is explicit. Loading does not imply success; disabled actions retain a readable explanation. Interactive controls retain focus and pressed feedback.

**Layout.** A list skeleton row has the geometry of a two-line `PaymentListItem`: 12 dp padding, a 20 dp square on the first line and bars centred in the label and caption lines, so content does not move when it loads. The fill is the outline tone, visible in light and dark.

## Do and don't

**Do**: Use the shape that matches the pending content to preserve layout.

**Don't**: Show a blank jump instead of the known pending shape.

## Content guidelines

Use sentence case and name the payment fact or action. Keep instructions visible and use semantic type, color and spacing tokens.

Use the shape that matches the pending content to preserve layout.

## Accessibility

- Screen readers hear one "Loading" (or `semanticLabel`) instead of a series of empty boxes.
