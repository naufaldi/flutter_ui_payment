Payment attempts as a detail module. Variants: pending, ready, empty, error. Composes DataTable with pagination null and no selection. Your app handles row actions, retry and Create. Module errors use warning tone. Extra actions render as a dropdown.

## Usage

```dart
// example/lib/screens/gallery_views.dart
PaymentDetailPageTable<int>(
    title: 'Attempts',
    pending: pending,
    errorText: error ? 'Attempts didn’t load' : null,
    onRetry: () {},
    columns: [
      PaymentDataColumn<int>(
        key: 'time',
        label: 'Time',
        value: (r) => DateTime(2026, 10, 1, 10, r),
        cell: PaymentCellType.date,
      ),
      PaymentDataColumn<int>(
        key: 'method',
        label: 'Method',
        value: (r) => 'BCA virtual account',
        pinned: true,
      ),
      PaymentDataColumn<int>(
        key: 'status',
        label: 'Status',
        value: (r) => r == 3 ? 'Paid' : 'Pending',
        cell: PaymentCellType.status,
        statusMap: {'Paid': StatusTone.success, 'Pending': StatusTone.warning},
      ),
      PaymentDataColumn<int>(
        key: 'amount',
        label: 'Amount',
        value: (r) => const Money.idr(102500),
        cell: PaymentCellType.currency,
      ),
    ],
    rows: empty ? const [] : const [1, 2, 3],
    rowKey: (r) => '$r',
    rowActions: [
      PaymentRowAction<int>(
        id: 'view',
        label: 'View attempt',
        onPressed: (_) {},
      ),
    ],
  );
```

## Variants

Variants: pending, ready, empty, error.

### States and content

This detail module composes `PaymentDataTable` without paging or selection. Use the standalone data table when those interactions are needed.

## Which variant when

| Situation | Variant / composition | Payment example |
| --- | --- | --- |
| Payment attempts | ready | Use direct columns and explicit status mapping; the module omits paging and selection. |

Use Data table for selectable settlement pages.

## States

Use pending while attempts load. An empty result explains that there are no attempts; a failed load shows a warning and a host retry action.

## Do and don't

**Do**: Use direct columns and explicit status mapping; the module omits paging and selection.

**Don't**: Add a duplicate Attempts wrapper heading.

## Content guidelines

Name each attempt's reference, method, time and status. Use an explicit unknown label when no result is confirmed.

## Accessibility

Keep the attempt status in words and retain column labels when rows collapse on phones.

Show an unknown status as an explicit label in the neutral tone.
