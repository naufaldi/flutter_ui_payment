## Usage

### Minimal

Add the [published package](/start/installation/), then paste this complete example into `lib/main.dart`.

```dart standalone
import 'package:flutter/material.dart';
import 'package:rakit_ui/rakit_ui.dart';

void main() => runApp(MaterialApp(
  home: Scaffold(
    appBar: AppBar(title: const Text('Example')),
    body: Builder(builder: (context) => Padding(
      padding: const EdgeInsets.all(16),
      child: PaymentButton(
        label: 'Note actions',
        variant: PaymentButtonVariant.secondary,
        onPressed: () => showPaymentSheet<void>(
          context: context,
          builder: (sheetContext) => PaymentSheet(
            header: PaymentSheetHeader(
              title: 'Note actions',
              onClose: () => Navigator.of(sheetContext).pop(),
            ),
            body: const Text('Choose what to do with this note.'),
            footer: PaymentButton(
              label: 'Done',
              onPressed: () => Navigator.of(sheetContext).pop(),
            ),
          ),
        ),
      ),
    )),
  ),
));
```

## Variants

Variants: bottom sheet, side sheet.

### Behavior

- The header's **Close** only closes the panel. Cancelling a payment is a separate footer action, behind `showPaymentConfirmDialog`, and your host decides the result. The payment stays pending until then.
- `showPaymentSheet` sizes the sheet to its content, up to the full height. Swipe down, the scrim, Back and Escape dismiss it while `isDismissible` is true.
- `showPaymentSideSheet` takes the same `PaymentSheet`, which then fills the height so the footer sits at the bottom. The scrim, Back and Escape close it, and focus returns to whatever opened it.
- Both presenters keep the theme around the code that opens them: a `PaymentTheme` or `PaymentButtonTheme` scoped to one feature also styles that feature's sheet surface and buttons.
- Pass `isDismissible: false` / `barrierDismissible: false` while a host call that must finish is running.
- Sheets open in 280 ms and close in 200 ms on the drawer curve; zero under reduced motion.
- The header's title centres its first line on the 48 dp close button at every text scale. The header keeps that height while `onClose` is null, so hiding Close during a host call does not move the title.
- On phones, `showPaymentConfirmDialog` and `PaymentMenu` open as sheets too. A confirmation opened from a sheet stacks on top of it.

### Footer: one primary

The footer's completion action is the sheet's one primary button ("Done", "Apply"). The button that opened the sheet stays secondary. Use a quiet button for "Cancel" or "Not now".

## States

The host supplies content and handles actions. Closing a sheet dismisses its UI; it does not cancel a payment.

## Do and don't

**Do**: Use the provided presentation functions; close never cancels a payment operation.

**Don't**: Attach a destructive payment action to the close affordance.

## Content guidelines

- Title the sheet with what it shows or asks: "Pending payment", "Filter transactions".
- Use `subtitle` for one line of context, such as a reference or a date.
- Put the actions in the footer, the main one as the primary. Keep the footer to one or two buttons.
- Never label the close button or any footer action in a way that suggests closing cancels a payment. Write the cancel request as its own action, such as "Request cancellation".

## Accessibility

Keep the close control labeled and the footer reachable with the keyboard open. Dismissal returns focus to the opener.
