`PaymentSheet` lays out a header, a scrolling body and a fixed footer, with safe-area and keyboard insets handled. Open it as a bottom sheet or as a side panel from the end edge.

## Usage

```dart
await showPaymentSheet<void>(
  context: context,
  builder: (sheet) => PaymentSheet(
    header: PaymentSheetHeader(
      title: 'Pending payment',
      onClose: () => Navigator.pop(sheet),
    ),
    body: const Text('Closing this panel does not cancel the payment.'),
    footer: PaymentButton(
      label: 'Request cancellation',
      variant: PaymentButtonVariant.secondary,
      // Do not return the Future: PaymentButton would show a spinner while
      // the confirmation dialog is open.
      onPressed: () => unawaited(confirmThenAskHost(sheet)),
    ),
  ),
);
```

`unawaited` comes from `dart:async`.

## Behavior

- The header's **Close** only closes the panel. Cancelling a payment is a separate footer action, behind `showPaymentConfirmDialog`, and your host decides the result. The payment stays pending until then.
- `showPaymentSheet` sizes the sheet to its content, up to the full height. Swipe down, the scrim, Back and Escape dismiss it while `isDismissible` is true.
- `showPaymentSideSheet` takes the same `PaymentSheet`, which then fills the height so the footer sits at the bottom. The scrim, Back and Escape close it, and focus returns to whatever opened it.
- Pass `isDismissible: false` / `barrierDismissible: false` while a host call that must finish is running.
- Sheets open in 280 ms and close in 200 ms on the drawer curve; zero under reduced motion.

## Content guidelines

- Title the sheet with what it shows or asks: "Pending payment", "Filter transactions".
- Use `subtitle` for one line of context, such as a reference or a date.
- Put the actions in the footer, the main one last. Keep the footer to one or two buttons.
- Never label the close button or any footer action in a way that suggests closing cancels a payment. Write the cancel request as its own action, such as "Request cancellation".
