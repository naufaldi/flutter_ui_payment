Use semantic tokens from the kit. Never invent raw colors, sizes or weights.

The scale is **4 / 8 / 12 / 16 / 24 / 32** on the 8 base: an 8 pt grid with 4 pt half-steps, so `block` (12) is on the grid (D46). Every kit spacing value resolves through `theme.space(PaymentSpace.<role>)`, and **one role uses one value**: icon → text uses `block` (12) in the toast, banner, state message, accordion, skeleton, list row and status header alike.

| The gap is… | Role |
| --- | --- |
| No gap | `none` |
| Within one label | `inline` |
| Between related rows or actions | `related` |
| Between an icon and row text, or row padding | `block` |
| A gutter, or between a label and its value | `group` |
| Before a primary action or a ruled section | `section` |
| The largest reserved gap | `major` |

## Radius roles

`PaymentTheme.radius` (default 8) is the `box` role and the base of the others. A theme may set `tagRadius`, `controlRadius` or `sheetRadius` to change one role; an unset role keeps its multiple: tag 0.5 (4), control 0.75 (6), sheet 1.5 (12). `PaymentRadius` and the theme getters (`tagBorderRadius`, `controlBorderRadius`, `borderRadius`, `sheetBorderRadius`) resolve the current role. See [Corner roles](/concepts/theming/#corner-roles).

Each 64 CSS pixel square shows the top-left corner of a 48 dp tile at **8× magnification (8 CSS pixels per dp)**. The window covers 8 dp in each direction, making small radii visible. The unbounded `circle` token (999, pill) is shown separately as a complete 64 px circle, rather than a corner detail.

## Component sizes

Heights and boxes are component sizes, not spacing roles, so they are not `PaymentSpace` values. They sit on the 4 grid: **36** (small button, `InfoRow` pitch), **40** (media tile), **48** (minimum target, list row, small field), **52** (the `_ControlRow` control column), **56** (medium field, large button), **60** (video play disc) and **64** (large list row, large field). A two-line list row is 62 dp (12 + 20 + 18 + 12): its parts are on the grid, and the loading skeleton copies it. The spacing scale and standard component heights use the 4 dp grid. Fixed bar thicknesses and strokes are exceptions: `StatusBand` is 6 dp high (`primitives.dart:1063`), and the step bar is 3 dp high (`payment_extras.dart:349`). These are component details, not spacing roles.

## Stripe mapping

| Stripe size | PaymentSpace |
| --- | --- |
| xxsmall | inline |
| xsmall | related |
| small | block |
| medium | group |
| large | section |
| xlarge, xxlarge | major |

| Stripe radius | PaymentRadius |
| --- | --- |
| none | none |
| xsmall | tag |
| small | control |
| medium | box |
| large | sheet |
| rounded | circle |

Use theme.space to preserve the host base unit. The default gutter is 16 at every width. Nested radii must be concentric: inner rounding is smaller than outer rounding. Sections stay flat and separated by space.

Do: `EdgeInsets.all(theme.space(PaymentSpace.group))`, the named version of existing screen gutters. Don't: `EdgeInsets.all(16)`.

```dart
final theme = PaymentTheme.of(context);
final gutter = EdgeInsets.all(theme.space(PaymentSpace.group));
```

Size is small, medium (default), large; width is fill (default) or hug. All labels wrap. `PaymentButton` and fields already consume `PaymentSize`; interactive layout and hit boxes remain at least 48×48 dp regardless of visual size. `PaymentBox` implements token-based padding, gaps, radius and width.
