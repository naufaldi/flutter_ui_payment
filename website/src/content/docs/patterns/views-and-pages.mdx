---
title: Views and pages
description: Mount bounded payment bodies with a single scroll region and host-owned routing.
---

D31: views and pages are Scaffold-free bodies. The host supplies the Scaffold, tab, route or sheet. Mount a view in a bounded body so its content owns one scroll region. Only showPaymentFocusView presents a focused task itself.

```dart
// example/lib/screens/flow_screen.dart
SizedBox.expand(
  key: ValueKey('flow-view-${c.step.name}'),
  child: _StepBody(coordinator: c),
);
```

Use DetailPage at the top level, never inside FullPageView. Put non-scrolling OverviewPage inside FullPageView, as A01 history does. Primary/secondary module lists accept page modules, detail property lists, detail tables and chart modules. Do not wrap an already titled module in another title.

| Task | Composition |
| --- | --- |
| History and spending (A01) | FullPageView → OverviewPage → ChartModule, followed by filters and TransactionHistory |
| Transaction (A02) | DetailPage → payment module, attempts table, merchant properties |
| Edit settings (A05) | SettingsView → grouped controls, one Save footer |
| Report (A02) | FocusView → facts, category, message, Send and Cancel |

The phone footer stacks full-width primary then secondary actions. Supporting context beside wide checkout carries no second Pay action.
